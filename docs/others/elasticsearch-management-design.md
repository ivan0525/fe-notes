# Elasticsearch 管理模块设计方案

> 嵌入运维系统的 ES 管理模块，面向业务方用户，通过后端代理对接 ES 官方 API。

---

## 1. 设计背景与目标

### 1.1 背景

团队已部署官方 Elasticsearch 服务，业务方在日常工作中需要查看集群状态、管理索引、查询数据，但当前缺少统一的可视化管理入口。Kibana 虽提供相关能力，但 UX 对业务方过于复杂，且无法融入现有运维系统的统一体验。

### 1.2 目标

在现有运维系统中新增 ES 管理模块，提供以下核心能力：

| 能力 | 说明 |
|------|------|
| 集群监控 | 集群健康概览 + 节点级基础指标 |
| 索引管理 | 索引的创建、删除、mapping 查看与编辑 |
| 查询工具 | 可视化查询构建器 + DSL 编辑器 + 查询模板 |

### 1.3 设计原则

- **业务友好**：目标用户非技术深度用户，所有交互应降低 ES 概念门槛
- **安全优先**：所有请求经后端代理，不暴露 ES 端口，操作可审计
- **渐进增强**：可视化查询为主、DSL 为辅，新手和高级用户各取所需
- **统一体验**：使用运维系统自研前端框架，保持 UI/UX 一致性

## 2. 整体架构

### 2.1 架构选型决策：后端代理模式

**决策：采用后端代理模式，前端不直连 ES。**

理由：
- 前端直连 ES 等于将集群 root 权限暴露给浏览器，业务方可通过 DevTools 发任意请求
- 后端代理可实现：操作审计、请求校验（拦截危险操作）、结果大小裁剪、查询超时控制
- 与运维系统现有后端架构保持一致

### 2.2 架构拓扑

```
┌─────────────────────────────────────────────────────┐
│                   运维系统前端                        │

│  └────┬─────┘  └────┬─────┘  └───────┬──────────┘   │
│       │              │                │              │
```

### 2.3 后端代理层职责

| 职责 | 说明 |
|------|------|
| 请求校验 | 拦截危险操作（如 `_delete_by_query` 无条件删除），限制 `size` 上限 |
| 操作审计 | 记录所有写操作（创建/删除索引、修改 mapping）到审计日志 |
| 结果裁剪 | 查询结果超过阈值时截断，防止大结果集撑爆前端内存 |
| 超时控制 | 所有转发到 ES 的请求设置统一超时（建议 30s），防止慢查询阻塞 |
| 限流 | 每用户/每分钟的请求频率限制，防止误操作连续刷请求 |

## 3. 功能模块详细设计

### 3.1 集群监控

#### 3.1.1 监控粒度决策

**决策：采用"中等偏轻"方案——集群概览 + 节点级基础指标，不下沉到 segment/thread pool 级别。**

理由：
- 业务方关心的是"ES 是否可用"和"资源是否充足"，不需要运维级别的调优指标
- segment、thread pool、circuit breaker 等属于运维/SRE 的关注点
- 保持界面简洁，避免信息过载

#### 3.1.2 集群概览卡片

调用 ES API：`GET _cluster/health` + `GET _cluster/stats`

| 指标 | 数据来源 | 展示形式 |
|------|----------|----------|
| 集群健康状态 | `_cluster/health → status` | 信号灯（绿/黄/红）+ 文字说明 |
| 节点数 | `_cluster/health → number_of_nodes` | 数字 |
| 索引数 | `_cluster/health → active_primary_shards` 推导 | 数字 |
| 总文档数 | `_cluster/stats → indices.docs.count` | 格式化数字（如 12.5M） |
| 总存储用量 | `_cluster/stats → indices.store.size_in_bytes` | 格式化（如 256.3 GB） |
| 可用磁盘空间 | `_nodes/stats/fs` | 进度条（已用/总量） |

**健康状态说明规则：**

| 状态 | 含义 | 前端展示 |
|------|------|----------|
| Green | 所有主分片和副本分片正常 | 🟢 健康 |
| Yellow | 所有主分片正常，部分副本分片未分配 | 🟡 警告 — 副本不完整 |
| Red | 部分主分片不可用 | 🔴 异常 — 数据可能不可用 |

#### 3.1.3 节点列表

调用 ES API：`GET _nodes/stats`

| 列 | 数据来源 | 说明 |
|----|----------|------|
| 节点名称 | `nodes.{id}.name` | — |
| IP 地址 | `nodes.{id}.transport_address` | — |
| 角色 | `nodes.{id}.roles` | master / data / ingest 等 |
| CPU 使用率 | `nodes.{id}.os.cpu.percent` | 百分比 + 迷你进度条 |
| JVM 堆内存 | `nodes.{id}.jvm.mem.heap_used_percent` | 百分比 + 迷你进度条 |
| 磁盘使用率 | `nodes.{id}.fs.total` | 已用/总量 |
| 文档数 | `nodes.{id}.indices.docs.count` | 该节点上的文档数 |
| 分片数 | `_cat/allocation` 关联 | 该节点承载的分片数 |

#### 3.1.4 分片分配概览

调用 ES API：`GET _cat/shards?format=json`

以表格形式展示，按索引分组：

| 列 | 说明 |
|----|------|
| 索引名 | 分组标题 |
| 分片编号 | 0, 1, 2, ... |
| 类型 | Primary / Replica |
| 状态 | STARTED / UNASSIGNED / RELOCATING / INITIALIZING |
| 节点 | 分片所在节点名 |
| 文档数 | 该分片的文档数 |
| 大小 | 该分片的存储大小 |

**交互：**
- 默认折叠，点击索引名展开查看分片详情
- UNASSIGNED 分片高亮红色标记
- 支持按状态筛选（只看异常分片）

#### 3.1.5 数据刷新策略

| 策略 | 说明 |
|------|------|
| 手动刷新 | 页面提供"刷新"按钮，点击立即拉取最新数据 |
| 自动轮询 | 默认 30 秒轮询一次，可配置（15s / 30s / 60s / 关闭） |
| 首次加载 | 进入页面时自动拉取 |

### 3.2 索引管理

#### 3.2.1 索引列表页

调用 ES API：`GET _cat/indices?format=json&h=index,health,status,pri,rep,docs.count,store.size,creation.date.string`

| 列 | 说明 |
|----|------|
| 索引名 | 支持搜索过滤 |
| 健康状态 | green/yellow/red 信号灯 |
| 状态 | open / close |
| 主分片数 | — |
| 副本数 | — |
| 文档数 | 格式化显示 |
| 存储大小 | 格式化显示 |
| 创建时间 | — |
| 操作 | 查看 mapping / 删除 |

**交互：**
- 顶部搜索栏：支持按索引名模糊搜索
- 支持按健康状态、索引状态筛选
- 隐藏系统索引（以 `.` 开头的索引）默认不显示，可切换显示
- 分页加载（每页 20 条）

#### 3.2.2 创建索引

调用 ES API：`PUT /{index_name}`

**决策：采用表单化创建 + JSON 高级模式双轨方案。**

**表单模式（推荐业务方使用）：**

```
┌─ 创建索引 ──────────────────────────────────────┐
│                                                  │
│  索引名称:  [__________________________]         │
│             · 仅支持小写字母、数字、-、_          │
│             · 不能以 -、_、. 开头                 │
│                                                  │
│  主分片数:  [1    ▼]  (默认 1，建议 1-5)         │
│  副本数:    [1    ▼]  (默认 1)                   │
│                                                  │
│  ── Mapping 字段定义 ──                          │
│  ┌──────────┬──────────┬───────────┬────┐        │
│  │ 字段名    │ 字段类型  │ 分词器     │ 操作│       │
│  ├──────────┼──────────┼───────────┼────┤        │
│  │ title    │ text   ▼ │ standard▼ │ 🗑 │        │
│  │ status   │ keyword▼ │    —      │ 🗑 │        │
│  │ count    │ integer▼ │    —      │ 🗑 │        │
│  │ created  │ date   ▼ │    —      │ 🗑 │        │
│  └──────────┴──────────┴───────────┴────┘        │
│  [+ 添加字段]                                     │
│                                                  │
│  支持的字段类型:                                   │
│  text / keyword / integer / long / float /       │
│  double / boolean / date / object / nested       │
│                                                  │
│  分词器选项 (仅 text 类型):                        │
│  standard / ik_max_word / ik_smart / whitespace   │
│                                                  │
│              [取消]  [预览 JSON]  [创建]           │
└──────────────────────────────────────────────────┘
```

**JSON 高级模式：**

- 提供一个 JSON 编辑器，允许直接编写完整的 `settings` + `mappings` JSON
- 带语法校验（JSON 合法性 + ES mapping 基本规则校验）
- 表单模式切换到 JSON 模式时自动生成对应 JSON，方便学习

**创建前校验规则：**

| 规则 | 说明 |
|------|------|
| 索引名格式 | 仅允许小写字母、数字、`-`、`_`，不能以 `-`、`_`、`.` 开头 |
| 索引名重复 | 提交前检查索引是否已存在 |
| 字段名唯一 | mapping 中不允许重复字段名 |
| 主分片数范围 | 1-10，超出提示风险 |

#### 3.2.3 删除索引

调用 ES API：`DELETE /{index_name}`

**决策：二次确认 + 输入索引名确认，无回收站。**

理由：
- 回收站机制需要额外的快照/备份基础设施，复杂度过高
- 采用"输入索引名确认"的方式（类似 GitHub 删除仓库）已足够防止误操作

**交互流程：**

```
1. 点击"删除"按钮
2. 弹出确认对话框：
   ┌─ 删除索引 ──────────────────────────────┐
   │                                          │
   │  ⚠️ 此操作不可恢复！                      │
   │                                          │
   │  即将删除索引: my-index                   │
   │  包含 125,000 条文档，占用 2.3 GB          │
   │                                          │
   │  请输入索引名称以确认删除:                  │
   │  [__________________________]             │
   │                                          │
   │              [取消]  [确认删除]            │
   └──────────────────────────────────────────┘
3. 输入的索引名必须完全匹配才能点击"确认删除"
```

#### 3.2.4 Mapping 查看与管理

调用 ES API：`GET /{index_name}/_mapping`

**Mapping 查看页：**

以树形结构展示 mapping，每个字段显示：
- 字段名
- 字段类型（带类型图标/标签）
- 分词器（如适用）
- 是否可搜索（`index: true/false`）
- 子字段（`fields` / `properties`）

**Mapping 修改：**

ES 的 mapping 一旦创建，已有字段的类型不可修改，只能新增字段。UI 需要明确传达这个限制：

```
┌─ Mapping 管理 ─ my-index ──────────────────┐
│                                              │
│  现有字段 (不可修改类型):                      │
│  ├── title      text (ik_max_word)    🔒     │
│  ├── status     keyword               🔒     │
│  ├── count      integer               🔒     │
│  └── created    date                  🔒     │
│                                              │
│  ── 新增字段 ──                               │
│  ┌──────────┬──────────┬───────────┬────┐    │
│  │ 字段名    │ 字段类型  │ 分词器     │ 操作│   │
│  ├──────────┼──────────┼───────────┼────┤    │
│  │ [      ] │ [    ▼]  │ [     ▼]  │ 🗑  │   │
│  └──────────┴──────────┴───────────┴────┘    │
│  [+ 添加字段]                                 │
│                                              │
│  ⓘ ES 的 mapping 已有字段类型不可修改，        │
│    如需修改请创建新索引并迁移数据。              │
│                                              │
│                    [取消]  [提交新增字段]       │
└──────────────────────────────────────────────┘
```

调用 ES API：`PUT /{index_name}/_mapping`（仅新增字段）

面向不熟悉 DSL 的业务方，通过表单交互自动生成查询。

```
│  │ created▼ │ 范围   ▼  │ [起] ～ [止]      │ 🗑  │     │
```

**操作符映射到 DSL：**

| 字段类型 | 可用操作符 | 对应 DSL |

| integer/long/float/double | 等于 / 大于 / 小于 / 范围 | `term` / `range` |
| date | 等于 / 早于 / 晚于 / 范围 | `range` |
| boolean | 是 / 否 | `term` |

**"查看生成的 DSL"按钮：**

#### 3.3.3 DSL 编辑器

面向有一定技术背景的用户，提供原始 DSL 编写能力。

**编辑器功能要求：**

| 功能 | 说明 |
|------|------|
| 语法高亮 | JSON 语法着色 |
| 自动补全 | ES 关键字补全（`match`、`term`、`range`、`bool` 等） |
| JSON 校验 | 实时检测 JSON 格式错误，标红提示 |
| 格式化 | 一键美化/压缩 JSON |
| 折叠 | 支持代码块折叠 |
| 历史记录 | 最近 20 条查询历史，可快速回填 |

**推荐实现：** 集成 Monaco Editor（VS Code 同款编辑器引擎），配置 JSON language server，自定义 ES DSL 的自动补全 provider。

**安全限制（后端代理层实现）：**

| 限制 | 规则 |
|------|------|
| `size` 上限 | 最大 500，超过自动截断为 500 并提示 |
| 超时 | 查询超过 30s 自动取消 |
| 禁止操作 | 拦截 `_delete_by_query`、`_update_by_query`（不通过查询工具暴露写操作） |
| 仅允许 `_search` | 查询工具仅转发 `GET /{index}/_search` 请求 |

#### 3.3.4 查询模板

预置常用查询模板，用户填入参数即可执行，降低上手门槛。

**内置模板：**

| 模板名称 | 说明 | 参数 |
|----------|------|------|
| 全文搜索 | 在指定字段中搜索关键词 | 字段、关键词 |
| 精确匹配 | 按 keyword 字段精确查找 | 字段、值 |
| 时间范围查询 | 按时间字段筛选指定范围的数据 | 时间字段、起止时间 |
| 多条件组合查询 | AND/OR 组合多个条件 | 条件列表 |
| TopN 聚合 | 统计某字段出现次数最多的 N 项 | 字段、N |
| 日期趋势统计 | 按天/小时统计文档数量趋势 | 时间字段、时间间隔 |

**自定义模板：**

- 用户可将任意查询"保存为模板"
- 模板包括：名称、描述、DSL 内容（参数用 `{{placeholder}}` 标记）
- 模板存储在运维系统后端数据库，可在团队内共享

#### 3.3.5 查询结果展示

**决策：表格为默认视图 + JSON 树形视图切换 + 聚合结果图表可视化。**

**文档结果（hits）：**

| 视图 | 说明 |
|------|------|
| 表格视图（默认） | 自动将 `_source` 展平为列，列可排序/调整宽度/选择显示隐藏 |
| JSON 视图 | 可折叠的 JSON 树形展示，展示原始返回 |

表格视图处理规则：
- 顶层标量字段直接作为列
- 嵌套对象用 `.` 路径展示（如 `address.city`）
- 数组字段显示为 `[3 items]`，点击展开
- 超长文本截断显示，hover 查看全文

**聚合结果（aggregations）：**

| 聚合类型 | 图表类型 |
|----------|----------|
| `terms` | 柱状图 / 饼图（可切换） |
| `date_histogram` | 折线图 / 面积图 |
| `avg` / `sum` / `max` / `min` | 数字卡片 |
| `range` | 柱状图 |

**结果操作栏：**

```
共命中 12,500 条，本次返回 200 条  |  耗时 23ms
[表格视图] [JSON视图]  |  导出: [CSV] [JSON]  |  [复制为 cURL]
```

**导出限制：** 单次导出最多 500 条（与查询上限一致），需要更多数据引导使用 scroll/导出工具。

### 4.1 API 总览

所有 API 统一前缀：`/api/es`

| 模块 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 集群 | GET | `/api/es/cluster/health` | 集群健康状态 |

| 集群 | GET | `/api/es/nodes/stats` | 节点列表及指标 |
| 集群 | GET | `/api/es/shards` | 分片分配信息 |
| 索引 | GET | `/api/es/indices` | 索引列表（支持分页、搜索、筛选） |
| 索引 | POST | `/api/es/indices` | 创建索引 |
| 索引 | DELETE | `/api/es/indices/{name}` | 删除索引 |
| 索引 | GET | `/api/es/indices/{name}/mapping` | 获取 mapping |

### 4.2 关键 API 请求/响应示例

#### 创建索引

```
POST /api/es/indices
Content-Type: application/json

{
  "name": "my-index",
  "settings": {
    "number_of_shards": 1,
    "number_of_replicas": 1
  },
  "mappings": {
    "properties": {
      "title": { "type": "text", "analyzer": "ik_max_word" },
      "status": { "type": "keyword" },
      "count": { "type": "integer" },
      "created": { "type": "date" }
    }
  }
}
```

#### 执行查询

```
POST /api/es/indices/my-index/search
Content-Type: application/json

{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "搜索关键词" } },
        { "term": { "status": "active" } }
      ],
      "filter": [
        { "range": { "created": { "gte": "2024-01-01", "lte": "2024-12-31" } } }
      ]
    }
  },
  "sort": [{ "created": "desc" }],
  "size": 200,
  "_source": ["title", "status", "count", "created"]
}
```

**后端代理处理逻辑：**

```
1. 校验 JSON 合法性
2. 校验 size ≤ 500，超过截断
3. 注入 timeout: "30s"
4. 转发到 ES: GET /my-index/_search
5. 记录审计日志: { user, index, query_hash, timestamp, took_ms }
6. 返回结果（保持 ES 原始响应结构）
```

## 6. 关键交互流程

### 6.1 可视化查询 → DSL 生成流程

```
用户在可视化构建器中:
  1. 选择索引 → 自动加载该索引的 mapping (GET /api/es/indices/{name}/mapping)
  2. mapping 字段列表填充到"字段"下拉框
  3. 根据字段类型动态调整可用"操作符"和"值输入组件"
     - text 类型 → 文本输入框
     - keyword 类型 → 文本输入框（或枚举下拉，如有）
     - date 类型 → 日期选择器
     - boolean 类型 → 开关/下拉
     - number 类型 → 数字输入框
  4. 用户配置条件后，前端实时生成 DSL JSON (dslBuilder.ts)
  5. 点击"查看生成的 DSL"可预览/复制
  6. 点击"查询"提交到后端代理
```

### 6.2 创建索引流程

```
  1. 点击"创建索引"按钮
  2. 弹出创建对话框 (表单模式)
  3. 填写索引名 → 前端实时校验格式
  4. 配置分片数、副本数
  5. 添加 mapping 字段 (可选)
  6. 点击"预览 JSON"查看将要发送的请求体
  7. 点击"创建" → 后端校验索引名唯一性 → 调用 ES PUT API
  8. 成功 → 关闭对话框，刷新索引列表
  9. 失败 → 展示 ES 返回的错误信息
```
