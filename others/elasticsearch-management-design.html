# Elasticsearch 管理模块设计方案

嵌入运维系统的 ES 管理模块，面向业务方用户，通过后端代理对接 ES 官方 API。

# 1. 设计背景与目标

# 1.1 背景

团队已部署官方 Elasticsearch 服务，业务方在日常工作中需要查看集群状态、管理索引、查询数据，但当前缺少统一的可视化管理入口。Kibana 虽提供相关能力，但 UX 对业务方过于复杂，且无法融入现有运维系统的统一体验。

# 1.2 目标

在现有运维系统中新增 ES 管理模块，提供以下核心能力：

能力说明
集群监控集群健康概览 + 节点级基础指标
索引管理索引的创建、删除、mapping 查看与编辑
查询工具可视化查询构建器 + DSL 编辑器 + 查询模板

# 1.3 设计原则

  • 业务友好：目标用户非技术深度用户，所有交互应降低 ES 概念门槛
  • 安全优先：所有请求经后端代理，不暴露 ES 端口，操作可审计
  • 渐进增强：可视化查询为主、DSL 为辅，新手和高级用户各取所需
  • 统一体验：使用运维系统自研前端框架，保持 UI/UX 一致性

# 2. 整体架构

# 2.1 架构选型决策：后端代理模式

决策：采用后端代理模式，前端不直连 ES。

理由：

  • 前端直连 ES 等于将集群 root 权限暴露给浏览器，业务方可通过 DevTools 发任意请求
  • 后端代理可实现：操作审计、请求校验（拦截危险操作）、结果大小裁剪、查询超时控制
  • 与运维系统现有后端架构保持一致

# 2.3 后端代理层职责

职责说明
请求校验拦截危险操作（如 _delete_by_query 无条件删除），限制 size 上限
操作审计记录所有写操作（创建/删除索引、修改 mapping）到审计日志
结果裁剪查询结果超过阈值时截断，防止大结果集撑爆前端内存
超时控制所有转发到 ES 的请求设置统一超时（建议 30s），防止慢查询阻塞
限流每用户/每分钟的请求频率限制，防止误操作连续刷请求

# 3. 功能模块详细设计

# 3.1 集群监控

# 3.1.1 监控粒度决策

决策：采用"中等偏轻"方案——集群概览 + 节点级基础指标，不下沉到 segment/thread pool 级别。

理由：

  • 业务方关心的是"ES 是否可用"和"资源是否充足"，不需要运维级别的调优指标
  • segment、thread pool、circuit breaker 等属于运维/SRE 的关注点
  • 保持界面简洁，避免信息过载

# 3.1.2 集群概览卡片

调用 ES API：GET _cluster/health + GET _cluster/stats

指标数据来源展示形式
集群健康状态_cluster/health → status信号灯（绿/黄/红）+ 文字说明
节点数_cluster/health → number_of_nodes数字
索引数_cluster/health → active_primary_shards 推导数字
总文档数_cluster/stats → indices.docs.count格式化数字（如 12.5M）
总存储用量_cluster/stats → indices.store.size_in_bytes格式化（如 256.3 GB）
可用磁盘空间_nodes/stats/fs进度条（已用/总量）

健康状态说明规则：

状态含义前端展示
Green所有主分片和副本分片正常🟢 健康
Yellow所有主分片正常，部分副本分片未分配🟡 警告 — 副本不完整
Red部分主分片不可用🔴 异常 — 数据可能不可用

# 3.1.3 节点列表

调用 ES API：GET _nodes/stats

列数据来源说明
节点名称nodes.{id}.name—
IP 地址nodes.{id}.transport_address—
角色nodes.{id}.rolesmaster / data / ingest 等
CPU 使用率nodes.{id}.os.cpu.percent百分比 + 迷你进度条
JVM 堆内存nodes.{id}.jvm.mem.heap_used_percent百分比 + 迷你进度条
磁盘使用率nodes.{id}.fs.total已用/总量
文档数nodes.{id}.indices.docs.count该节点上的文档数
分片数_cat/allocation 关联该节点承载的分片数

# 3.1.4 分片分配概览

调用 ES API：GET _cat/shards?format=json

以表格形式展示，按索引分组：

列说明
索引名分组标题
分片编号0, 1, 2, ...
类型Primary / Replica
状态STARTED / UNASSIGNED / RELOCATING / INITIALIZING
节点分片所在节点名
文档数该分片的文档数
大小该分片的存储大小

交互：

  • 默认折叠，点击索引名展开查看分片详情
  • UNASSIGNED 分片高亮红色标记
  • 支持按状态筛选（只看异常分片）

# 3.1.5 数据刷新策略

策略说明
手动刷新页面提供"刷新"按钮，点击立即拉取最新数据
自动轮询默认 30 秒轮询一次，可配置（15s / 30s / 60s / 关闭）
首次加载进入页面时自动拉取

# 3.2.3 删除索引

调用 ES API：DELETE /{index_name}

决策：二次确认 + 输入索引名确认，无回收站。

理由：

  • 回收站机制需要额外的快照/备份基础设施，复杂度过高
  • 采用"输入索引名确认"的方式（类似 GitHub 删除仓库）已足够防止误操作

交互流程：

1. 点击"删除"按钮
2. 弹出确认对话框：
   ┌─ 删除索引 ──────────────────────────────┐
   │                                          │
   │  ⚠️ 此操作不可恢复！                      │
   │                                          │
   │  即将删除索引: my-index                   │
   │  包含 125,000 条文档，占用 2.3 GB          │
   │                                          │
   │  请输入索引名称以确认删除:                  │
   │  [__________________________]             │
   │                                          │
   │              [取消]  [确认删除]            │
   └──────────────────────────────────────────┘
3. 输入的索引名必须完全匹配才能点击"确认删除"

# 3.3.3 DSL 编辑器

面向有一定技术背景的用户，提供原始 DSL 编写能力。

编辑器功能要求：

功能说明
语法高亮JSON 语法着色
自动补全ES 关键字补全（match、term、range、bool 等）
JSON 校验实时检测 JSON 格式错误，标红提示
格式化一键美化/压缩 JSON
折叠支持代码块折叠
历史记录最近 20 条查询历史，可快速回填

推荐实现： 集成 Monaco Editor（VS Code 同款编辑器引擎），配置 JSON language server，自定义 ES DSL 的自动补全 provider。

安全限制（后端代理层实现）：

限制规则
size 上限最大 500，超过自动截断为 500 并提示
超时查询超过 30s 自动取消
禁止操作拦截 _delete_by_query、_update_by_query（不通过查询工具暴露写操作）
仅允许 _search查询工具仅转发 GET /{index}/_search 请求

# 6. 关键交互流程

# 6.1 可视化查询 → DSL 生成流程

用户在可视化构建器中:
  1. 选择索引 → 自动加载该索引的 mapping (GET /api/es/indices/{name}/mapping)
  2. mapping 字段列表填充到"字段"下拉框
  3. 根据字段类型动态调整可用"操作符"和"值输入组件"
     - text 类型 → 文本输入框
     - keyword 类型 → 文本输入框（或枚举下拉，如有）
     - date 类型 → 日期选择器
     - boolean 类型 → 开关/下拉
     - number 类型 → 数字输入框
  4. 用户配置条件后，前端实时生成 DSL JSON (dslBuilder.ts)
  5. 点击"查看生成的 DSL"可预览/复制
  6. 点击"查询"提交到后端代理

# 6.2 创建索引流程

  1. 点击"创建索引"按钮
  2. 弹出创建对话框 (表单模式)
  3. 填写索引名 → 前端实时校验格式
  4. 配置分片数、副本数
  5. 添加 mapping 字段 (可选)
  6. 点击"预览 JSON"查看将要发送的请求体
  7. 点击"创建" → 后端校验索引名唯一性 → 调用 ES PUT API
  8. 成功 → 关闭对话框，刷新索引列表
  9. 失败 → 展示 ES 返回的错误信息
